# FunPay Monitor

VK-бот для мониторинга цен на игровом маркетплейсе [FunPay](https://funpay.com): следит за лотами и игровой валютой, хранит историю цен и присылает уведомления, когда цена падает ниже порога, падает на N% или обновляет исторический минимум.

> Учебный проект (итоговый/дипломный). **MVP заморожен 13.11.2026**: парсер, воркер, бот, графики, алерты, админка, тесты, CI и документация готовы. Для живого прогона осталось заполнить `.env` и проверить токен через `scripts/check_vk.py`.

## Быстрый старт

### Через Docker

```bash
cp .env.example .env
docker compose up --build -d
```

> Реальные значения пишите в `.env`. `.env.example` — шаблон в git, его нельзя
> заполнять токенами.

Сервис `migrate` применит миграции Alembic, после чего стартуют бот (Long Poll)
и воркер (планировщик парсинга). Для бота нужен `VK_GROUP_TOKEN` в `.env`.

### Если Docker недоступен: Podman

```bash
sudo pacman -S podman
systemctl --user enable --now podman.socket
podman compose up --build -d
```

`podman compose` использует установленный `docker-compose` как провайдер и сам
подключает его к сокету Podman, поэтому compose-файл менять не нужно. Порт
`5432` должен быть свободен; автозапуск после перезагрузки настраивается
отдельно через systemd user unit или Quadlet.

### Локально

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

docker compose up -d db   # или podman compose up -d db
alembic upgrade head     # применить миграции

pytest          # тесты
ruff check .    # линтер

python -m app.main      # бот
python -m app.worker    # воркер, в отдельном терминале
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `VK_GROUP_TOKEN` | — | Ключ доступа сообщества VK (Long Poll) |
| `VK_GROUP_ID` | `0` | ID сообщества |
| `VK_ADMIN_IDS` | — | VK id админов для `/status` и `/reparse` (через запятую) |
| `DATABASE_URL` | `postgresql+asyncpg://funpay:funpay@localhost:5432/funpay` | DSN базы данных |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `PARSE_INTERVAL_MINUTES` | `15` | Интервал опроса FunPay |
| `REQUEST_DELAY_SECONDS` | `3` | Пауза между HTTP-запросами к FunPay |
| `ALERT_COOLDOWN_HOURS` | `6` | Минимальный интервал между алертами по одной подписке |

## Парсер FunPay

`FunPayParser` разбирает серверный HTML страниц `/chips/{id}/` и `/lots/{id}/`:

- офферы — `a.tc-item`, цена — `div.tc-price`, количество — `div.tc-amount` (`кк` нормализуется в миллионы);
- тип предложения — `data-f-type`, способ — `data-f-method`, название — `.tc-desc-text`;
- сервер — `data-server` + `div.tc-server`, продавец — `data-user` или ссылка на профиль;
- флаги `offer-promo` и онлайн-статус продавца;
- точная цена из `data-s` (до 6 знаков) и `numeric(18,6)` в БД;
- HTTP-клиент держит паузу между запросами и повторяет их с backoff при 429/5xx.

FunPay фильтрует типы предложений только в браузере, поэтому бот скачивает всю
страницу и сам выделяет нужный срез «тип + часть названия».

Ручной прогон без бота и БД:

```bash
python scripts/parse_once.py /chips/30/
python scripts/parse_once.py https://funpay.com/lots/13/
```

Тесты парсера работают на сохранённых HTML-фикстурах (`tests/fixtures/funpay/`) и не ходят в сеть.

## Воркер и мониторинг

`python -m app.worker` запускает APScheduler: первый прогон сразу, затем каждые
`PARSE_INTERVAL_MINUTES` (±2 мин jitter). Для каждой активной категории:

1. открывается запись в `parse_runs` (статус `running`);
2. страница парсится, серверы и текущие офферы сохраняются в БД;
3. по каждому серверу пишется базовый снапшот (min/median/offer count), плюс
   отдельные снапшоты для срезов активных подписок (тип и/или название);
4. прогон закрывается статусом `ok`, `error` или `partial`.

Если страница вернула 0 офферов или парсер упал, ошибка сохраняется в `parse_runs`,
а воркер продолжает работу со следующей категорией.

## Алерты

После каждого успешного парсинга категории воркер проверяет активные подписки:

- `abs` — минимальная цена стала ниже порога;
- `pct` — цена упала на N% относительно предыдущего снапшота;
- `lowest` — цена обновила исторический минимум (на первом снапшоте не срабатывает).

Если подписка ограничена типом предложения и/или названием, алерт считается
только по снапшотам этого среза. Устаревший снапшот, которого нет в последнем
прогоне, не вызывает уведомление.

Перед отправкой проверяется кулдаун `ALERT_COOLDOWN_HOURS` (по умолчанию 6 часов)
по журналу `notifications`. Уведомление приходит в VK с графиком min/median за
7 дней; если загрузить картинку не удалось, текст всё равно отправляется.
Отправленные алерты записываются в `notifications`, поэтому после перезапуска
воркер не дублирует их раньше времени.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и главное меню |
| `/add` или ссылка FunPay | Парсит категорию, предлагает тип, название, сервер, условие и порог, сохраняет подписку |
| `/list` | Активные подписки с текущими ценами и кнопками «Статистика» / «Удалить» |
| `/stats <id>` | Текущая цена и график min/median за 7 дней |
| `/unsubscribe <id>` | Мягко удаляет подписку |
| `/help` | Справка по командам и форматам ссылок |
| `/status` | Админ: категории, пользователи, подписки, последние запуски |
| `/reparse <id или ссылка>` | Админ: перепарсить категорию и проверить алерты |

Сценарий `/add`: ссылка → тип предложения (если есть) → часть названия (или
«Пропустить») → сервер (или «Любой») → режим (`abs`, `pct`, `lowest`) → порог →
подтверждение. Состояние диалога хранится в state dispenser vkbottle и не
переживает перезапуск процесса — это осознанное упрощение для дипломного MVP.

Ссылку можно присылать в виде `https://funpay.com/chips/30/`, `https://funpay.com/lots/13/`
или просто `/chips/30/`. Бот сам скачает страницу, создаст категорию и серверы в БД,
если воркер ещё не успел это сделать.

## Настройка сообщества VK

1. Создать сообщество → «Управление» → «Сообщения сообщества»: включить.
2. «Работа с API» → Long Poll API: включить; создать ключ доступа сообщества.
3. Ключ положить в `.env` (`VK_GROUP_TOKEN`), ID сообщества — в `VK_GROUP_ID`.
4. Пользователь должен написать боту первым — VK не даёт сообществу писать тому, кто не начинал диалог.

Проверить ключ и Long Poll без запуска бота:

```bash
python scripts/check_vk.py
```
