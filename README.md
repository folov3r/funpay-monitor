# FunPay Monitor

Настольное приложение для Windows и Linux, которое следит за ценами на
игровом маркетплейсе [FunPay](https://funpay.com). Программа хранит историю
цен в локальной базе SQLite, показывает графики и присылает уведомление,
когда товар дешевеет.

Один и тот же интерфейс открывается двумя способами:

- в отдельном окне приложения (Tauri);
- в браузере по адресу `http://127.0.0.1:8765`.

Сервер и внешняя база данных не нужны: всё работает на компьютере
пользователя.

## Возможности

- отслеживание категорий FunPay `/chips/…` (игровая валюта) и `/lots/…`
  (предметы и услуги);
- фильтры по серверу, типу предложения и части названия;
- текущий срез: минимум, медиана, количество предложений и самые дешёвые
  лоты;
- подписки на категорию целиком, на конкретный сервер или на любой сервер;
- три условия уведомления: цена ниже порога, падение на N%, новый
  исторический минимум;
- график минимальной и медианной цены за 7 дней;
- системные уведомления Windows и Linux, а также журнал уведомлений внутри
  приложения;
- автоматический парсинг по расписанию (по умолчанию каждые 15 минут);
- локальная база SQLite: история цен сохраняется между запусками;
- работа в системном трее: закрытие окна скрывает приложение, выход
  останавливает фоновый процесс.

## Как это работает

```
┌────────────────────────────┐
│ Окно приложения (WebView)  │──┐
└────────────────────────────┘  │  HTTP
┌────────────────────────────┐  │
│ Браузер                    │──┤
│ http://127.0.0.1:8765      │  │
└────────────────────────────┘  ▼
                        ┌──────────────────┐
                        │ Локальный API    │
                        │ FastAPI +        │
                        │ планировщик      │
                        └────────┬─────────┘
                                 │
                        ┌────────▼─────────┐        ┌─────────┐
                        │ SQLite           │        │ FunPay  │
                        │ история и        │◄──────►│ (HTTP)  │
                        │ подписки         │        └─────────┘
                        └──────────────────┘
```

При запуске окно Tauri стартует Python-ядро. Ядро поднимает локальный API на
`127.0.0.1:8765`, открывает базу и запускает планировщик. Фронтенд общается
с ядром по HTTP, поэтому его же можно открыть в обычном браузере.

## Установка

### Готовые сборки

Скачайте установщик со страницы
[Releases](https://github.com/folov3r/group-project/releases):

- Windows — `.msi` или `.exe`;
- Linux — `.deb` или `.AppImage`.

При первом запуске Windows может показать предупреждение SmartScreen:
установщик не подписан сертификатом. На Linux для `.AppImage` может
потребоваться `chmod +x`.

### Запуск из исходников

Понадобятся Python 3.12+, Node.js 20+ и, для окна Tauri, Rust 1.77+.

Linux дополнительно требует WebKitGTK и GTK 3:

```bash
# Arch
sudo pacman -S webkit2gtk-4.1 gtk3 libayatana-appindicator
# Debian / Ubuntu
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev
```

Python-ядро:

```bash
python3.12 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python -m app.desktop
```

После этого интерфейс доступен в браузере: `http://127.0.0.1:8765`.
Каталог базы можно задать флагом `--data-dir` или переменной
`FUNPAY_DATA_DIR`.

Окно приложения в режиме разработки:

```bash
cd frontend
npm install
npm run tauri dev
```

В dev-режиме Tauri запускает Vite и Python-ядро из `.venv` автоматически.
Если Python не найден, укажите интерпретатор переменной `FUNPAY_PYTHON`.

### Сборка установщика

```bash
pip install -e ".[build]"
python scripts/build_core.py     # один исполняемый файл Python-ядра
cd frontend
npm run tauri:build
```

`build_core.py` собирает ядро через PyInstaller и кладёт его в
`frontend/src-tauri/binaries/`. Готовые установщики появляются в
`frontend/src-tauri/target/release/bundle/`.

Сборку нужно выполнять на той же ОС, для которой предназначен установщик:
Windows-пакет собирается на Windows, Linux-пакет — на Linux.

## Как пользоваться

1. Откройте вкладку «Категории» и вставьте ссылку на категорию FunPay,
   например `https://funpay.com/chips/30/`.
2. Программа сразу скачает страницу и покажет текущие предложения, график и
   сводку. При необходимости выберите сервер, тип или название.
3. Перейдите во вкладку «Подписки», выберите категорию и условие
   уведомления.
4. Вкладка «Уведомления» показывает историю срабатываний, вкладка
   «Состояние» — последние прогоны парсера и ошибки.

Системное уведомление приходит, когда условие подписки выполнено. Повторные
уведомления по одной подписке ограничены кулдауном (по умолчанию 6 часов).

## Где хранятся данные

Приложение создаёт базу `funpay-monitor.sqlite3` в пользовательском каталоге:

| ОС | Путь |
|---|---|
| Windows | `%APPDATA%\com.funpaymonitor.desktop\funpay-monitor.sqlite3` |
| Linux | `~/.local/share/com.funpaymonitor.desktop/funpay-monitor.sqlite3` |

При запуске ядра без Tauri используется каталог `funpay-monitor`
(`~/.local/share/funpay-monitor` на Linux). Его можно переопределить
переменной `FUNPAY_DATA_DIR` или флагом `--data-dir`.

Для резервной копии закройте приложение и скопируйте файл базы. SQLite может
держать рядом служебные файлы `-wal` и `-shm` — копируйте их вместе с базой,
если приложение было запущено.

## Локальный API

Ядро слушает только `127.0.0.1`, поэтому снаружи компьютера API недоступен.
Интерактивная документация — `http://127.0.0.1:8765/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | версия, тип базы, состояние планировщика |
| `GET` | `/api/status` | сводка и последние прогоны |
| `GET` | `/api/categories` | отслеживаемые категории |
| `POST` | `/api/categories/import` | добавить категорию по ссылке |
| `GET` | `/api/categories/{id}/summary` | минимум, медиана, количество |
| `GET` | `/api/categories/{id}/offers` | предложения с фильтрами |
| `GET` | `/api/categories/{id}/history` | история цен |
| `POST` | `/api/categories/{id}/reparse` | перепарсить категорию сейчас |
| `GET` | `/api/subscriptions` | подписки локального пользователя |
| `POST` | `/api/subscriptions` | создать подписку |
| `DELETE` | `/api/subscriptions/{id}` | отключить подписку |
| `GET` | `/api/subscriptions/{id}/stats` | сводка и график подписки |
| `GET` | `/api/notifications` | журнал уведомлений |

## Настройка

Настройки читаются из переменных окружения и файла `.env` в каталоге
запуска.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `API_HOST` | `127.0.0.1` | адрес локального API |
| `API_PORT` | `8765` | порт локального API |
| `SCHEDULER_ENABLED` | `true` | запускать парсинг по расписанию |
| `PARSE_INTERVAL_MINUTES` | `15` | интервал парсинга |
| `REQUEST_DELAY_SECONDS` | `3` | пауза между запросами к FunPay |
| `ALERT_COOLDOWN_HOURS` | `6` | кулдаун уведомлений по подписке |
| `HISTORY_DAYS` | `7` | глубина истории в интерфейсе и алертах |
| `LOCAL_USER_VK_ID` | `0` | идентификатор локального пользователя |
| `FUNPAY_DATA_DIR` | — | каталог базы данных |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Тесты

```bash
pytest                       # unit-тесты, без внешней базы
ruff check .
ruff format --check .
```

Тесты на SQLite работают всегда. Интеграционные тесты PostgreSQL включаются
переменной `TEST_DATABASE_URL` и относятся к оставшемуся в репозитории
VK-боту:

```bash
TEST_DATABASE_URL="postgresql+asyncpg://funpay:funpay@localhost:5432/funpay_test" pytest
```

Проверка фронтенда:

```bash
cd frontend
npm run typecheck
npm run build
```

## Структура проекта

```
app/
  api/          # локальный HTTP API: маршруты, схемы, уведомления
  db/           # модели SQLAlchemy и репозитории (SQLite и PostgreSQL)
  parsers/      # BaseParser, парсер FunPay, HTTP-клиент
  services/     # мониторинг, условия алертов, графики
  bot/          # VK-бот (дополнительный канал, не входит в desktop-сборку)
  desktop.py    # entrypoint Python-ядра
  worker.py     # отдельный воркер VK-бота
frontend/
  src/          # React + TypeScript, общий интерфейс
  src-tauri/    # Rust-оболочка Tauri, иконки, конфигурация сборки
scripts/        # сборка ядра, проверка VK, разовый парсинг
tests/          # pytest и HTML-фикстуры FunPay
docs/           # документация MkDocs Material
```

## Ограничения

- источник данных только FunPay; второй маркетплейс подключается через
  `BaseParser`;
- парсер зависит от вёрстки FunPay: при её изменении прогон получает статус
  `error`, а причина видна во вкладке «Состояние»;
- одновременно может работать только один экземпляр приложения: порт
  `8765` занят;
- автоматических обновлений и бэкапов нет;
- уведомления Linux требуют работающего демона уведомлений;
- VK-бот остаётся в репозитории как дополнительный канал, но desktop-сборка
  его не запускает и не требует токен VK.
