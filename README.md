# FunPay Monitor

VK-бот, который следит за ценами на игровом маркетплейсе [FunPay](https://funpay.com):
хранит историю лотов и игровой валюты и присылает уведомление, когда цена
опускается ниже порога, падает на заданный процент или обновляет исторический
минимум.

## Что умеет

- парсит категории FunPay `/chips/…` (игровая валюта) и `/lots/…` (лоты);
- фильтрует предложения по типу и части названия;
- показывает текущий срез: количество предложений, минимум, медиану и три
  самых дешёвых лота;
- создаёт подписки на категорию целиком, на конкретный сервер или на любой
  сервер;
- поддерживает три режима алертов: ниже порога, падение на N%, новый
  исторический минимум;
- присылает уведомление с графиком минимальной и медианной цены за 7 дней;
- не спамит: на одну подписку действует кулдаун;
- даёт админам команды `/status` и `/reparse`;
- запускается через Docker Compose или Podman Compose.

## Как это работает

```
                 ┌──────────────┐
   VK Long Poll  │     bot      │
  ◄─────────────►│  команды,    │
                 │  диалог /add │
                 └──────┬───────┘
                        │
                 ┌──────▼───────┐
                 │  PostgreSQL  │
                 │  подписки,   │
                 │  история цен │
                 └──────┬───────┘
                        │
                 ┌──────▼───────┐      HTTP      ┌─────────┐
                 │    worker    │───────────────►│ FunPay  │
                 │  планировщик │                └─────────┘
                 └──────┬───────┘
                        │ VK API
                        ▼
                  уведомления в VK
```

`bot` и `worker` — два независимых процесса. Они не общаются напрямую и не
делят память: единственная точка обмена — PostgreSQL. Поэтому любой из них
можно перезапустить отдельно, а парсинг не блокирует ответы бота.

1. Пользователь присылает боту ссылку на категорию FunPay.
2. Бот сразу скачивает страницу, сохраняет категорию, серверы и текущие
   предложения в базу и показывает, что сейчас происходит с ценой.
3. Пользователь выбирает фильтр, сервер, условие и порог. Подписка сохраняется.
4. Воркер по расписанию перепарсивает активные категории, обновляет текущие
   предложения и записывает снапшоты min/median/count.
5. После каждого успешного прогона воркер проверяет подписки и отправляет
   уведомления тем, чьё условие сработало.

## Из чего состоит

| Компонент | Назначение |
|---|---|

| `app/worker.py` | процесс воркера: APScheduler, парсинг, проверка алертов |
| `app/parsers/` | источник данных: `BaseParser`, парсер FunPay и HTTP-клиент |
| `app/services/` | мониторинг, условия алертов, графики, загрузка фото в VK |
| `app/db/` | ORM-модели и репозитории SQLAlchemy |
| `alembic/` | миграции схемы PostgreSQL |
| `scripts/` | ручная проверка VK и разовый парсинг категории |
| `tests/` | unit- и интеграционные тесты, HTML-фикстуры FunPay |
| `docs/` | документация MkDocs Material |

### Бот

Бот работает в сообществе VK через Long Poll, поэтому ему не нужен публичный
HTTPS-домен и входящие соединения. Он принимает команды, ведёт пошаговый диалог
добавления подписки и отправляет графики. Состояние диалога хранится в памяти
процесса: после перезапуска незаконченный `/add` начинается заново.

### Воркер

Воркер запускает APScheduler: первый прогон сразу, затем каждые
`PARSE_INTERVAL_MINUTES` (±2 минуты jitter). Категории обрабатываются
последовательно с паузой между HTTP-запросами. Результат каждого прогона
пишется в `parse_runs`; ошибка одной категории не останавливает остальные.

### Парсер

`FunPayParser` разбирает серверный HTML страниц `/chips/{id}/` и `/lots/{id}/`:

- предложения — `a.tc-item`;
- цена — `.tc-price`, точное значение — `data-s` (до 6 знаков);
- количество — `.tc-amount`, суффиксы `кк`/`млн` нормализуются;
- тип — `data-f-type`, способ — `data-f-method`, название — `.tc-desc-text`;
- сервер — `data-server` и `.tc-server`;
- продавец, онлайн-статус и промо-флаг.

Подпись поля выбора берётся со страницы: на Albion это «Сервер», на Roblox —
«Способ передачи». Если у категории такого поля нет, шаг выбора сервера
пропускается. HTML разбирается в отдельном потоке, чтобы большая страница не
тормозила Long Poll.

`BaseParser` — общий интерфейс источника. Чтобы добавить второй маркетплейс,
достаточно реализовать `fetch_category()` и `aclose()`.

### База данных

| Таблица | Что хранит |
|---|---|
| `users` | пользователи VK |
| `categories` | отслеживаемые категории FunPay |
| `servers` | серверы или способы передачи внутри категории |
| `offers` | текущие предложения, перезаписываются при каждом прогоне |
| `price_snapshots` | история min/median/count по серверу и срезу |
| `parse_runs` | журнал запусков парсера и ошибок |
| `subscriptions` | подписки и условия алертов |
| `notifications` | отправленные уведомления и кулдаун |

Денежные значения хранятся в `numeric(18, 6)`, количество — в `numeric(18, 2)`.
История не удаляется при обновлении текущих предложений.

## Быстрый старт

### Docker Compose

```bash
cp .env.example .env
# заполните VK_GROUP_TOKEN, VK_GROUP_ID и VK_ADMIN_IDS
docker compose up --build -d
docker compose logs -f bot worker
```

Compose поднимает четыре сервиса:

- `db` — PostgreSQL 16;
- `migrate` — применяет `alembic upgrade head` и завершается;
- `bot` — обработчик команд;
- `worker` — планировщик парсинга и алертов.

### Podman Compose

Если Docker недоступен, подойдёт rootless Podman:

```bash
sudo pacman -S podman
systemctl --user enable --now podman.socket
podman compose up --build -d
podman compose ps
```

`podman compose` использует установленный `docker-compose` как провайдер и сам
подключает его к сокету Podman, поэтому compose-файл менять не нужно. Сокет
обязательно должен быть запущен, иначе compose не подключится к API. Порт
`5432` должен быть свободен.

### Без контейнеров

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# PostgreSQL 16 должен быть доступен, DSN — в DATABASE_URL
alembic upgrade head

python -m app.main      # бот
python -m app.worker    # воркер, в отдельном терминале
```

Бот и воркер общаются только через PostgreSQL, поэтому контейнеры не обязательны.

## Настройка VK

1. Создайте сообщество или используйте существующее.
2. «Управление» → «Сообщения сообщества»: включите сообщения.
3. «Управление» → «Работа с API» → «Long Poll API»: включите и выберите версию.
4. Создайте ключ доступа сообщества с правами на сообщения.
5. Заполните `.env`: `VK_GROUP_TOKEN`, `VK_GROUP_ID`, `VK_ADMIN_IDS`.

Пользователь должен написать сообществу первым: VK не разрешает сообществу
инициировать диалог. Проверить ключ и Long Poll без запуска бота:

```bash
python scripts/check_vk.py
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `VK_GROUP_TOKEN` | — | Ключ доступа сообщества VK (Long Poll) |
| `VK_GROUP_ID` | `0` | ID сообщества |
| `VK_ADMIN_IDS` | — | VK id админов для `/status` и `/reparse` (через запятую) |
| `DATABASE_URL` | `postgresql+asyncpg://funpay:funpay@localhost:5432/funpay` | DSN базы данных |
| `POSTGRES_USER` | `funpay` | Пользователь PostgreSQL для compose |
| `POSTGRES_PASSWORD` | `funpay` | Пароль PostgreSQL для compose |
| `POSTGRES_DB` | `funpay` | Имя базы для compose |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `PARSE_INTERVAL_MINUTES` | `15` | Интервал опроса FunPay |
| `REQUEST_DELAY_SECONDS` | `3` | Пауза между HTTP-запросами к FunPay |
| `ALERT_COOLDOWN_HOURS` | `6` | Минимальный интервал между алертами по подписке |
| `CHAT_CLEANUP_ENABLED` | `true` | Удалять сообщения диалога `/add` после сохранения |

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и главное меню |
| `/add` или ссылка FunPay | Парсит категорию, предлагает фильтр, сервер, условие и порог, сохраняет подписку |
| `/list` | Активные подписки с текущими ценами и кнопками «Статистика» / «Удалить» |
| `/stats <id>` | Текущая цена и график min/median за 7 дней |
| `/unsubscribe <id>` | Мягко удаляет подписку |
| `/help` | Справка по командам и форматам ссылок |
| `/status` | Админ: категории, пользователи, подписки, последние запуски |
| `/reparse <id или ссылка>` | Админ: перепарсить категорию и проверить алерты |

Ссылку можно присылать как `https://funpay.com/chips/30/`,
`https://funpay.com/lots/13/` или просто `/chips/30/`.

## Сценарий добавления подписки

1. Ссылка на категорию.
2. Тип предложения — если на странице есть `data-f-type` (например,
   «Предметы», «Услуги», «Гайды»); кнопка «Все» пропускает фильтр.
3. Часть названия — например `plush nessie`; кнопка «Пропустить» оставляет все
   предложения выбранного типа.
4. Сервер или способ передачи — кнопкой либо текстом; «Любой» снимает
   ограничение.
5. Условие: ниже порога, падение на N% или новый исторический минимум.
6. Порог в рублях или процентах (для нового минимума не нужен).
7. Подтверждение и сохранение.

Сразу после ввода названия бот показывает текущий срез: количество, минимум,
медиану и три самых дешёвых предложения. Для категорий без шага названия
(`/chips/…`) такой же срез показывается сразу после проверки ссылки.

После успешного сохранения бот удаляет свою часть диалога, оставляя итоговое
сообщение. Сообщения пользователя VK удалять сообществу не разрешает, поэтому
они остаются. Чистку можно отключить флагом `CHAT_CLEANUP_ENABLED=false`.

## История цен и алерты

После каждого успешного парсинга воркер:

1. закрывает запись в `parse_runs` статусом `ok`, `error` или `partial`;
2. пишет базовые снапшоты по каждому серверу;
3. пишет отдельные снапшоты для срезов активных подписок (тип и/или название);
4. проверяет подписки категории.

Условия срабатывания:

- `abs` — минимальная цена стала ниже порога;
- `pct` — цена упала на N% относительно предыдущего снапшота;
- `lowest` — цена обновила исторический минимум (на первом снапшоте не
  срабатывает).

Перед отправкой проверяется кулдаун `ALERT_COOLDOWN_HOURS` по журналу
`notifications`, поэтому после перезапуска воркер не дублирует недавние
уведомления. Если в новом прогоне в срезе не осталось предложений, алерт по
устаревшей цене не отправляется.

Уведомление приходит с графиком min/median за 7 дней. Если загрузить картинку
не удалось, текст всё равно отправляется.

## Тесты

```bash
pytest                                   # unit-тесты, без БД
TEST_DATABASE_URL="postgresql+asyncpg://funpay:funpay@localhost:5432/funpay_test" pytest
```

Первый запуск — 175 тестов на парсер, форматирование, бота и сервисы. Второй
добавляет 29 интеграционных тестов репозиториев, мониторинга и алертов на
PostgreSQL. Интеграционные тесты создают схему в указанной базе и удаляют её
после прогона, поэтому используйте отдельную базу (`funpay_test`, не `funpay`).

```bash
ruff check .
ruff format --check .
mkdocs build --strict
```

## Ограничения

- источник данных только FunPay; второй подключается через `BaseParser`;
- состояние диалога `/add` не переживает перезапуск бота;
- запускается один экземпляр воркера: блокировки задач между экземплярами нет;
- автоматических бэкапов нет, дамп PostgreSQL делается вручную;
- парсер зависит от вёрстки FunPay; при её изменении прогон получает статус
  `error` в `parse_runs`;
- сообщество VK не может удалять сообщения пользователя, чистка затрагивает
  только сообщения бота.
