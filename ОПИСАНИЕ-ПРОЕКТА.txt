FUNPAY MONITOR
Описание проекта для презентации и доклада


О ЧЕМ ПРОЕКТ

FunPay Monitor — это программа для компьютера, которая следит за ценами
на игровом маркетплейсе FunPay. Человек один раз настраивает подписку,
а программа сама проверяет цену и сообщает, когда товар становится
дешевле.

Раньше проект работал как бот в социальной сети VK. Теперь основная
версия — обычное приложение для Windows и Linux. VK-бот остался в
проекте как дополнительный канал и может быть подключён позже.


КАКУЮ ПРОБЛЕМУ РЕШАЕМ

На FunPay тысячи продавцов, и цены меняются в течение дня. Кто-то
переставил лот, кто-то выставил промо-предложение, дешёвый товар быстро
купили. Если человеку нужен конкретный предмет или игровая валюта, ему
приходится вручную открывать страницу и проверять цену.

Это неудобно по трём причинам:

1. Проверять нужно часто, а не один раз в день.
2. Категорий и продавцов много, глазами уследить сложно.
3. Готовые сервисы часто платные или требуют постоянного интернета
   и регистрации на чужом сайте.

Наша программа решает эту задачу: человек настраивает подписку, а дальше
всё происходит автоматически.


КОМУ ПОДХОДИТ

- игрокам, которые покупают игровую валюту или предметы;
- продавцам, которые следят за ценами конкурентов;
- людям, которые хотят видеть историю цены, а не только текущее число;
- тем, кто не хочет отдавать данные стороннему сервису.


ЧТО УМЕЕТ ПРОГРАММА

Коротко:

- принимает ссылку на категорию FunPay;
- показывает, какие предложения сейчас есть и сколько они стоят;
- даёт выбрать фильтр: тип товара, часть названия, сервер;
- создаёт подписку с одним из трёх условий срабатывания;
- периодически проверяет цену;
- присылает системное уведомление, когда условие выполнено;
- хранит историю цен и показывает её на графике;
- работает без интернета для просмотра уже собранных данных.

Программа не продаёт и не покупает товары. Она только наблюдает
за ценами и сообщает об изменениях.


КАК ПОЛЬЗУЕТСЯ ЧЕЛОВЕК

1. Открывает программу.
2. Вставляет ссылку на категорию, например:
   https://funpay.com/chips/30/
3. Программа читает страницу и показывает:
   - сколько сейчас предложений;
   - минимальную цену;
   - медианную цену;
   - самые дешёвые предложения;
   - график цены за последние дни.
4. Человек выбирает, что именно отслеживать:
   - тип предложения (например, «Предметы», «Услуги», «Гайды»);
   - часть названия (например, plush nessie);
   - сервер или способ передачи;
   - любой сервер, если ограничение не нужно.
5. Выбирает условие уведомления:
   - цена ниже заданного порога;
   - цена упала на заданный процент;
   - цена обновила исторический минимум.
6. Вводит порог, если он нужен, и сохраняет подписку.
7. Дальше подписка работает сама. Когда цена становится выгодной,
   на экране появляется системное уведомление, а запись о нём
   сохраняется в журнале программы.

Важно: программа не пишет продавцам и не покупает товары. Она только
показывает информацию и предупреждает о снижении цены.


ДВА ИНТЕРФЕЙСА — ОДИН ФУНКЦИОНАЛ

У программы два способа открыть интерфейс:

1. Окно приложения — обычное настольное окно. Его можно свернуть,
   закрыть в трей и открыть снова.
2. Браузер — тот же интерфейс по адресу http://127.0.0.1:8765.

Внутри используется один и тот же веб-интерфейс, поэтому не нужно
поддерживать две разные версии. Это экономит время разработки и
упрощает проверку.


ИЗ ЧЕГО СОСТОИТ СИСТЕМА

Система состоит из трёх частей.

1. Окно приложения (Tauri)

Это «рамка» программы. Окно показывает интерфейс, умеет работать
с системным треем и запускает остальные части. Внутри используется
системный браузерный движок Windows или Linux, поэтому программа
занимает меньше памяти, чем аналогичные решения на Electron.

2. Локальное ядро (Python)

Это «мозг» программы. Ядро:

- скачивает страницы FunPay;
- разбирает предложения и цены;
- сохраняет историю в базу;
- проверяет подписки;
- отправляет системные уведомления;
- отдаёт данные интерфейсу через локальный API.

3. База данных SQLite

Это один файл на компьютере пользователя. В нём хранятся категории,
предложения, история цен, подписки и журнал уведомлений. Отдельный
сервер базы данных не нужен: SQLite встроена в программу.

Схема работы:

   окно приложения  ─┐
                     ├──► локальный API ──► SQLite
   браузер          ─┘          │
                                ▼
                             FunPay

Локальный API принимает запросы только с этого же компьютера
(адрес 127.0.0.1). Снаружи, через интернет, он недоступен.


ПОЧЕМУ ТАКИЕ ТЕХНОЛОГИИ

Tauri вместо Electron

Electron тащит в каждую программу целый браузер Chromium. Tauri
использует браузерный движок, который уже есть в системе. Программа
получается легче, быстрее запускается и меньше ест память.

Python для ядра

На Python уже был готов парсер FunPay, работа с базой и логика
алертов. Переписывать всё на другом языке за 3–4 недели было бы
рискованно. Python позволяет быстро менять правила разбора страниц,
когда FunPay обновляет вёрстку.

FastAPI для локального API

FastAPI — лёгкий веб-фреймворк. Он даёт понятные адреса для запросов,
автоматическую проверку данных и удобную документацию. Интерфейс
и ядро общаются по обычному HTTP, поэтому их можно разрабатывать
и тестировать отдельно.

SQLite для хранения

SQLite не требует установки и настройки. Вся история лежит в одном
файле, который легко скопировать или сохранить в резервную копию.
Для одного пользователя на одном компьютере этого достаточно.

React и TypeScript для интерфейса

React помогает собирать интерфейс из небольших блоков, а TypeScript
ловит часть ошибок ещё до запуска программы. Графики строит библиотека
ECharts.

Rust в проекте

Rust используется только в оболочке Tauri. Команда не переписывала
на нём бизнес-логику: это позволило уложиться в срок и не тратить
время на изучение нового языка в критическом месте.


КАК ХРАНЯТСЯ ДАННЫЕ

Все данные лежат в файле funpay-monitor.sqlite3 в пользовательском
каталоге:

- Windows: %APPDATA%\com.funpaymonitor.desktop\
- Linux: ~/.local/share/com.funpaymonitor.desktop/

В базе есть таблицы:

- users — пользователи;
- categories — отслеживаемые категории;
- servers — серверы и способы передачи;
- offers — текущие предложения;
- price_snapshots — история минимальной и медианной цены;
- parse_runs — журнал запусков парсера;
- subscriptions — подписки и условия;
- notifications — отправленные уведомления.

Деньги хранятся не как дробные числа с плавающей точкой, а как целые
микро-рубли. Это защищает от ошибок округления: цена 0.000123 рубля
не превратится в 0.0001229999.

История цен не удаляется при обновлении текущих предложений. Поэтому
график показывает, как менялась цена, а не только последнее значение.


УВЕДОМЛЕНИЯ

Программа поддерживает два вида уведомлений:

1. Системное — всплывающее окно Windows или Linux.
2. Внутреннее — запись в журнале вкладки «Уведомления».

Чтобы не спамить, на одну подписку действует кулдаун. По умолчанию
повторное уведомление по той же подписке возможно не раньше чем через
6 часов. Кулдаун сохраняется в базе, поэтому не сбрасывается после
перезапуска программы.

Условия срабатывания:

- «ниже порога» — минимальная цена стала ниже заданного числа;
- «падение на N%» — цена упала на заданный процент по сравнению
  с прошлым измерением;
- «новый минимум» — цена стала самой низкой за всё время наблюдений.

На первом измерении режим «новый минимум» не срабатывает: сравнивать
ещё не с чем.


ПЛАНИРОВЩИК

Ядро само запускает проверку категорий по расписанию. По умолчанию —
каждые 15 минут. Первый прогон начинается сразу после запуска
программы.

Категории обрабатываются по очереди с паузой между запросами, чтобы
не создавать лишнюю нагрузку на FunPay. Результат каждого прогона
записывается в журнал. Если одна категория не разобралась, остальные
продолжают обрабатываться, а причина ошибки видна во вкладке
«Состояние».


БЕЗОПАСНОСТЬ И ПРИВАТНОСТЬ

- локальный API доступен только с этого компьютера;
- данные не отправляются на сторонние серверы;
- для работы не нужны аккаунт, регистрация или токен VK;
- база данных лежит в пользовательском каталоге и не требует прав
  администратора;
- приложение не покупает товары и не хранит платёжные данные.

Единственные внешние запросы — загрузка страниц FunPay для разбора цен.


ТЕСТИРОВАНИЕ И КАЧЕСТВО

В проекте есть автоматические тесты:

- парсер проверяется на сохранённых HTML-страницах FunPay;
- проверяются условия уведомлений, форматирование цен и дат;
- отдельные тесты проверяют локальный API: добавление категории,
  подписки, историю, уведомления;
- тесты базы работают на SQLite и PostgreSQL;
- проверяется сборка фронтенда и типы TypeScript.

Дополнительно настроены:

- линтер Python (ruff) — единый стиль кода;
- сборка документации;
- автоматический запуск проверок на GitHub Actions.

Ручной чек-лист помогает проверить программу перед показом: добавление
категории, фильтры, подписку, уведомление, перезапуск и сохранность
данных.


СРОКИ И РОЛИ В КОМАНДЕ

Проект выполнен командой из четырёх человек за 3–4 недели.

Роли:

- разработка ядра и API;
- разработка интерфейса и оболочки приложения;
- документация и презентация;
- проверка качества и тестирование.

Примерный план работ:

Неделя 1. Перенос базы на SQLite, локальный API, базовые экраны.
Неделя 2. Оболочка Tauri, запуск ядра, уведомления, графики.
Неделя 3. Сборка установщиков, тесты, исправление ошибок.
Неделя 4. Документация, проверка на Windows и Linux, подготовка показа.


ЧТО ПОЛУЧИЛОСЬ В ИТОГЕ

- работающее приложение для Windows и Linux;
- общий интерфейс для окна и браузера;
- локальная база без отдельного сервера;
- история цен и графики;
- три режима уведомлений;
- системные уведомления и журнал;
- автоматическая сборка установщика;
- тесты, документация и инструкция для нового разработчика.


ЧТО МОЖНО УЛУЧШИТЬ ДАЛЬШЕ

- добавить второй маркетплейс через общий интерфейс парсера;
- сделать автозапуск при входе в систему;
- добавить экспорт истории в CSV;
- сделать сравнение нескольких категорий на одном графике;
- подключить VK-бота как дополнительный канал уведомлений;
- добавить автоматическую проверку обновлений;
- сделать резервное копирование базы по расписанию.


КОРОТКО ДЛЯ ДОКЛАДА

FunPay Monitor — это настольная программа, которая следит за ценами
на FunPay. Пользователь добавляет ссылку на категорию, выбирает
условие, и программа сама проверяет цену по расписанию. История
хранится локально в SQLite, интерфейс открывается в окне приложения
или в браузере. Уведомления приходят системные и внутри программы.
Проект написан на Python, TypeScript и Rust, собирается в установщик
для Windows и Linux и не требует собственного сервера.
