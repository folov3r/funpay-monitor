# Ограничения

## Функциональные

- нет личного кабинета и сайта — только бот;
- нет VK Mini App;
- состояние диалога `/add` хранится в памяти и теряется при перезапуске;
- поддерживаются только публичные категории FunPay, без авторизации;
- второй источник данных (Steam) не реализован, но предусмотрен `BaseParser`;
- нет очереди отправки сообщений: при большом числе подписок потребуется
  ограничение скорости и retry.

## Данные

- офферы перезаписываются при каждом разборе, история хранится только в
  агрегированных снапшотах;
- минимум считается по всем офферам, включая промо; флаг `is_promo` сохранён
  для будущей фильтрации;
- JSON-LD `lowPrice` не используется из-за расхождения с таблицей.

## Эксплуатация

- один экземпляр воркера: параллельные запуски не координируются через БД;
- нет автоматического бэкапа PostgreSQL;
- нет внешнего health-check и алертов администратору о сбоях;
- нет деплоя в Kubernetes и горизонтального масштабирования.

## VK

- сообщество может писать только пользователю, который сам написал первым;
- лимиты VK API не тестировались под высокой нагрузкой;
- для живого запуска нужен ключ доступа сообщества и включённый Long Poll.

## Правовые замечания

Проект учебный. Он разбирает только публично доступные страницы FunPay с умеренной
частотой и не обходит авторизацию, капчу или платные ограничения. Перед публичным
запуском нужно свериться с правилами FunPay и VK, а также с законодательством о
персональных данных: бот хранит VK id и имя пользователя.

## Дальнейшее развитие

1. Второй парсер (Steam) как демонстрация расширяемости.
2. Аналитика: лучшие продавцы, сравнение серверов, разброс цен.
3. Очередь уведомлений и ограничение скорости.
4. Бэкапы и мониторинг.
5. Опционально — VK ID OAuth и личный кабинет.
