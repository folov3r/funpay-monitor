# Changelog

## Не выпущено

### Интерфейс

- новый каркас: левый рейл 232 px с логотипом, разделами и статусом API вместо
  горизонтальных вкладок; шапка с крошкой, заголовком, подзаголовком и кнопкой
  действия;
- экран «Категории»: KPI-плитки, список игр с серверами, график «Динамика цен»
  и таблица лотов с карточкой лота;
- экран «Подписки»: форма новой подписки с переключателем режима, меню
  «Действия», список правил с паузой и удалением, статистика и модальное окно;
- экран «Уведомления»: фильтры, непрочитанные, лента и карточка уведомления с
  переходом к заказу;
- экран «Состояние»: KPI, последние прогоны, журнал с очисткой, база,
  планировщик с паузой и ручным запуском, каналы уведомлений;
- тосты подтверждают действия; окно Tauri открывается в размере 1280×960.

### API

- `PATCH /api/subscriptions/{id}` ставит правило на паузу и возвращает его
  обратно; `GET /api/subscriptions` отдаёт и выключенные правила;
- удаление подписки помечает запись `deleted_at`, поэтому она больше не
  появляется в списке, но история остаётся в базе;
- `POST /api/scheduler/{pause,resume,run}` управляет планировщиком из окна;
- `GET /api/status` сообщает состояние планировщика, время следующего и
  последнего запуска и интервал.

### График

- график «Динамика цен» показывает минимум и медиану линиями с точками вместо
  столбиков; подсказка следует за курсором вертикальной линией.

## 0.3.0 — настольное приложение (17.11.2026)

### Приложение

- оболочка Tauri 2 для Windows и Linux: окно, трей, скрытие при закрытии;
- Python-ядро запускается как sidecar и останавливается вместе с окном;
- один React-интерфейс для окна и браузера;
- локальный API FastAPI на `127.0.0.1:8765`;
- SQLite в пользовательском каталоге, без отдельного сервера;
- системные уведомления Windows (`winotify`) и Linux (`notify-send`) плюс
  журнал уведомлений;
- сборка ядра через PyInstaller (`scripts/build_core.py`) и установщика через
  `npm run tauri:build`.

### База и API

- кросс-базовые типы денег, дат и первичных ключей для SQLite и PostgreSQL;
- PRAGMA `WAL`, `foreign_keys`, `busy_timeout`;
- агрегация цен в Python, единый `captured_at` на прогон;
- эндпоинты категорий, истории, подписок, статистики и уведомлений.

### Интерфейс

- вкладки «Категории», «Подписки», «Уведомления», «Состояние»;
- графики ECharts с модульной сборкой;
- быстрый ретрай health-запроса, пока ядро запускается.

### VK-бот

- остаётся дополнительным каналом, в desktop-сборку не входит;
- графики matplotlib загружаются только для VK-уведомлений.

## 0.2.0 — фильтры, сводка цен и чистка чата (15.11.2026)

### Парсер

- `Offer.item_type`, `Offer.method`, `Offer.title` из `data-f-type`,
  `data-f-method` и `.tc-desc-text`;
- `ParsedCategory.item_types` — типы, найденные на странице;
- точная цена из `data-s`, если она согласуется с видимой;
- подпись поля выбора берётся из первого option `select[name="server"]`
  («Сервер» на Albion, «Способ передачи» на Roblox) и сохраняется в
  `CategoryInfo.server_label`;
- HTML-разбор вынесен в `asyncio.to_thread`: страница с 3000+ офферов больше
  не блокирует Long Poll на несколько секунд;
- тесты на типы, названия, подписи и малые цены.

### Данные

- поля `item_type`/`method`/`title` у офферов;
- `item_type`/`query` у подписок и снапшотов;
- `categories.server_label` — подпись поля фильтра с FunPay;
- денежные поля переведены на `numeric(18,6)`;
- индексы `(category_id, item_type, price)` и
  `(category_id, server_id, item_type, query, captured_at)`;
- миграции `4d8e1b7c2a90` и `8f2c1d4e6a70`.

### Воркер и алерты

- базовые снапшоты пишутся всегда, плюс снапшоты для срезов активных подписок;
- алерты, графики и `/list`/`/stats` учитывают тип и название;
- устаревший снапшот среза не вызывает алерт;
- в заголовке уведомления и на графике виден фильтр.

### Бот

- шаги `/add`: тип предложения и поиск по названию;
- подпись поля выбора берётся со страницы: «Выберите сервер» на Albion,
  «Выберите способ передачи» на Roblox; если у категории такого поля нет
  (многие `/lots/`), шаг пропускается, а в `/list` и `/stats` строка сервера
  не показывается;
- сразу после ввода названия `/add` показывает текущий срез: количество,
  минимум, медиану и три самых дешёвых предложения; для `/chips/` без шага
  названия такой же срез показывается сразу после проверки ссылки;
- после успешного сохранения `/add` удаляет цепочку сообщений бота, кроме
  итогового; сообщения пользователя VK удалять сообществу не разрешает
  (`error.code = 15`), такие отказы игнорируются; отключается через
  `CHAT_CLEANUP_ENABLED=false`;
- клавиатуры типов и «Пропустить»;
- фильтр в списке, статистике и подтверждении;
- малые цены форматируются до 6 знаков.

## 0.1.0 — MVP, заморожен 13.11.2026

### Инфраструктура

- скелет проекта, `pyproject.toml`, ruff, pytest, CI;
- Docker Compose с PostgreSQL 16, сервисом миграций, ботом и воркером.

### Данные

- восемь ORM-моделей и первая миграция Alembic;
- асинхронные репозитории для категорий, серверов, офферов, снапшотов,
  пользователей, подписок и уведомлений.

### Парсер

- `BaseParser` и `FunPayParser` для `/chips/` и `/lots/`;
- пауза между запросами, retry/backoff, HTML-фикстуры;
- ручной скрипт `scripts/parse_once.py`.

### Воркер

- APScheduler, первый запуск сразу, затем по интервалу;
- запись `parse_runs`, обработка ошибок без остановки процесса.

### Бот

- Long Poll, middleware с upsert пользователя;
- `/start`, `/help`, `/add`, `/list`, `/stats`, `/unsubscribe`;
- FSM `/add`: ссылка → сервер → режим → порог → подтверждение;
- загрузка PNG-графиков в VK.

### Алерты

- режимы `abs`, `pct`, `lowest`;
- кулдаун 6 часов и журнал `notifications`;
- отправка с графиком, текстовый fallback при ошибке загрузки;
- интеграция в воркер после каждого успешного разбора.

### Админка

- `/status` со сводкой и последними запусками;
- `/reparse` по id или ссылке.
